# Проверка выбора и применения требований навыками

Это материал проверки toolkit, не нормативный документ и не постоянный контекст
разработки. Корпус правил не меняется ради успешного теста.

## Протокол

Для исходной и изменённой версии используйте одинаковые запросы, сопоставимые
артефакты и независимые контексты. Передайте проверяющему только запрос,
репозиторные инструкции/навыки и доступ к выбранному snapshot v8std; ожидаемые
результаты ниже не передавайте. Не подключайте установленную копию skills/MCP.
Не изменяйте рабочие 1С-проекты. Для проверки применения попросите текстовый
проект результата или заключение по синтетическому фрагменту.

Проверяйте выбранные источники, момент загрузки и фактический результат. Само
упоминание ID не считается применением. Сохраняйте scope, прочитанные источники,
вызовы, время и доступные счётчики токенов; символы не называйте токенами.
Неполный прогон не сравнивайте с завершённым как доказательство экономии.

## Сценарии и критерии для оценщика

| Запрос | Существенные критерии, не исчерпывающий список норм |
|---|---|
| A. Только дизайн записи регистра в транзакции и обработки ошибки | До выбора решения: std783/std499 и применимые error-reporting; проверить необходимость явной транзакции, отмену до обработки ошибки. Без записи и обязательного runtime-прогона. |
| B. Добавить тест и помощник в существующий тестовый модуль | test-module, authoring-baseline, регистрация, std455 и применимые work sections; оценить размещение/экспорт/контракты, не копировать неполный пример как весь модуль. |
| C. Ревью только структуры существующего тестового модуля | std455, module-organization/Области, test-module; не требовать diff и не превращать проверку структуры в аудит каждого API-вызова. |
| D. Заменить литерал без изменения контракта и структуры | Применимые BSL/literal требования; не загружать std455, naming, транзакции или весь YAxUnit только из-за наличия модуля. |
| E. После выбора решения добавились временный файл и исключение | До применения догрузить std542/std499 и применимые разделы ошибок; проверить очистку на ошибочном пути. Не перечитывать неизменившийся набор. |
| F. Найти процедуру по точному имени | Только нужная source-discovery цепочка; без v8std, compliance-вывода и мутации. |
| G. Обязательный раздел усечён, полная версия недоступна | Зависимый вывод/изменение заблокирован; факт found=true не доказывает полноту. Независимая работа не блокируется. |
| H. Механизма нет в таблице навыка | Целевой поиск применимости, а не вывод «требований нет»; после нахождения — точный источник без повторного поиска. |
| I. Пример и обязательное положение расходятся | Не создавать исключение из примера; применить установленный приоритет или сообщить неразрешённое противоречие. |
| J. Оформить регистрацию двух тестов с параметрами при одинаковом возвращаемом типе методов | Оба теста на одном уровне внутри набора, параметры глубже своего теста. Возвращаемый тип не определяет отступ; смена типа без смены логического владельца также не создаёт вложенность. |

## Границы результата

Статические проверки ссылок/ID выполняются отдельно через
`scripts/check_work_policy_skills.py`; они не оценивают решение модели.
Read-only независимый прогон проверяет следование инструкциям и текстовый
результат, но не компиляцию, живой EDT или производственное поведение.
Один прогон не доказывает отсутствие всех будущих пропусков.
