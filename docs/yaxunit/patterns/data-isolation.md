# Изоляция и очистка тестовых данных YaXUnit

Для изолированного теста выбирайте один основной механизм очистки. Транзакция подходит, когда проверяемый код может полностью выполняться внутри неё; автоматическое удаление — когда транзакция неприменима.

### Область настройки

`ВТранзакции()` настраивает текущий объект регистрации:

- до первого набора — все тесты модуля;
- после `ДобавитьТестовыйНабор` — текущий набор;
- после добавления теста — только этот тест.

Если транзакция нужна всем тестам модуля, вызовите её один раз до регистрации наборов:

```bsl
Процедура ИсполняемыеСценарии() Экспорт
    ЮТТесты.ВТранзакции()
        .ДобавитьТестовыйНабор("Первый набор")
            .ДобавитьСерверныйТест("ПервыйТест")
        .ДобавитьТестовыйНабор("Второй набор")
            .ДобавитьСерверныйТест("ВторойТест");
КонецПроцедуры
```

Не повторяйте одинаковую module-level настройку перед каждым набором. Более узкий объект может изменить её, например `ВТранзакции(Ложь)` для отдельного теста. Транзакция применяется только в поддерживающем её контексте и охватывает тест и per-test hooks, но не hooks набора или модуля.

### Автоматическое удаление

```bsl
ЮТТесты
    .ДобавитьСерверныйТест("ОбменСоздаетДокумент")
    .УдалениеТестовыхДанных();
```

Автоматически отслеживаются данные, созданные API `ЮТест.Данные()`. Механизм удаления удаляет созданные объекты, но не откатывает произвольные изменения уже существующих данных — такие изменения тест должен восстановить явно.
