# Базовый контракт авторинга тестов YaXUnit

- Размещайте тест в тестовом общем модуле владельца тестов, определённого проектом; не меняйте продукт или ядро YaXUnit без отдельного запроса.
- Экспортная процедура `ИсполняемыеСценарии()` должна только декларативно зарегистрировать именованный набор, тесты, параметры, теги, контексты, hooks и настройки через `ЮТТесты`.
- Каждый зарегистрированный тестовый метод экспортный, проверяет одно наблюдаемое поведение и не зависит от порядка выполнения других тестов.
- Начинайте обычные проверки с `ЮТест.ОжидаетЧто(...)`. Присутствие, отсутствие, количество, поля или строки данных базы проверяйте через `ЮТест.ОжидаетЧтоТаблицаБазы(...)` и `ЮТУтвержденияИБ`, а не запросом с последующей общей проверкой коллекции.
- Если тест записывает persistent data, до реализации выберите подходящую изоляцию и очистку; транзакция и отслеживаемое удаление не являются универсальным откатом.
- Мокируйте внешнюю границу, только когда это требуется для изоляции; не заменяйте mock-ом поведение под тестом.
- Неизвестную или version-sensitive сигнатуру проверяйте по API-карточке, а при недостатке или конфликте snapshot — по установленному ядру проекта.

Детали загружайте только по механизму задачи: `test-module`, `naming`, `registration-and-parameters`, `assertions`, `test-data`, `data-isolation`, `mocking`, `predicates-and-queries`, `dependencies`, `lifecycle-and-contexts` или `test-analysis-and-migration`.
