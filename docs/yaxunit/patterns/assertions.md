# Утверждения и проверка исключений YaXUnit

Начинайте цепочку с `ЮТест.ОжидаетЧто`: это создаёт корректный контекст `ЮТУтверждения` и позволяет добавить понятное сообщение об ошибке.

### Значения и свойства

```bsl
ЮТест.ОжидаетЧто(Результат, "Результат расчета")
    .ЭтоНеНеопределено()
    .Свойство("Сумма")
    .Равно(100);
```

### Вызов без исключения

```bsl
ЮТест.ОжидаетЧто(ДокументОбъект)
    .Метод("Записать")
    .НеВыбрасываетИсключение();
```

### Ожидаемая ошибка

```bsl
ЮТест.ОжидаетЧто(Сервис)
    .Метод("ВыполнитьПроверку")
    .ВыбрасываетИсключение("Не заполнен обязательный параметр");
```

### Состояние базы

```bsl
Условие = ЮТест.Предикат()
    .Реквизит("Проведен").Равно(Истина);

ЮТест.ОжидаетЧтоТаблицаБазы("Документ.ЗаказКлиента")
    .СодержитЗаписи(Условие);
```

Для presence, absence, count, fields и row sets используйте `ОжидаетЧтоТаблицаБазы(...)` и специализированную цепочку `ЮТУтвержденияИБ`, включая `ЧтоТаблица(...)` при переключении таблицы. Не заменяйте такую проверку на `ЮТЗапросы.Записи(...)` с общей проверкой длины или коллекции. Запрос допустим, когда его результат сам является проверяемым API-результатом либо специализированная цепочка не выражает требуемое условие.

Сравнивайте бизнес-результат, а не промежуточные детали реализации. Для нескольких условий используйте fluent-цепочку или предикат, но сохраняйте одно диагностическое сообщение на одну логическую проверку.
