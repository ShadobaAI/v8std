# Именование тестов YaXUnit

- Сначала определите роль модуля. Тестовый модуль YaXUnit содержит `ИсполняемыеСценарии` и тестовые методы; вспомогательный модуль расширения реализует override, testability seam или функциональность вне основного продукта.
- Тестовый модуль YaXUnit именуйте по проверяемому объекту: префикс типа (`ОМ_`, `Спр_`, `Док_`, `РС_` и аналогичные), точное имя объекта и применимый суффикс модуля (`_МО`, `_ММ`, `_НЗ` и аналогичные). Не добавляйте project namespace расширения; префикс внутри имени проверяемого объекта сохраняйте.
- Вспомогательный модуль именуйте по правилам расширения-владельца. Project namespace обязателен только для этой роли и не превращает модуль в тестовый.
- Ядро YaXUnit сохраняет собственное пространство имён; правила тестовых модулей и объектов расширения к нему не применяются.
- Точное соответствие префиксов и суффиксов подтверждайте по соседним тестам владельца и установленному ядру, не угадывайте.
- Представление набора стройте как `Тип объекта ИмяОбъекта. [Тип модуля.] ИмяМетода()`.
- Имя тестовой процедуры стройте как `ИмяМетода_Сценарий`, а представление теста — как `ИмяМетода(). Ожидаемое поведение`.
- Предпочитайте ясное поведенческое представление попытке закодировать все условия в идентификаторе процедуры.
