# Переиспользовать шаги: экспортные сценарии, библиотеки и аргументы

Основание: MainHelp 1.2.043.1 и примеры `training/features/Примеры`. Правила экспорта/подстановок описаны документацией; выделение поведения в подсценарий — рекомендация. Примеры не подтверждают наличие всех шагов в установленной библиотеке.

## Найти реализацию до написания своего шага

Дерево известных шагов строится по загруженным библиотекам и показывает пример применения, описание, EPF реализации и вызываемую процедуру. Ищите действие/проверку по смыслу, затем проверяйте параметры. Для другого языка справка показывает режим вывода шагов сразу на двух языках. При исследовании реальной формы её исследователь показывает элементы, видимость/доступность и часто используемые шаги; для полноценной работы нужен подключённый TestClient.

Снипет получается из строки шага после удаления ключевого слова и параметров; библиотека связывает его с реализацией. Сообщение «Не найдена процедура или функция для выполнения шага» указывает на отсутствие соответствия: сначала проверьте опечатку и подключённую библиотеку, а не меняйте assertions.

На закладке «Библиотеки» задаются каталоги собственных шагов и общих экспортных сценариев. В основной поставке, отличной от Single, строка основной библиотеки обычно появляется автоматически. Прочитанный текст не определяет JSON-ключ, рекурсивность поиска или правила исключений — не выдумывайте их; сверяйте текущие настройки и результат загрузки.

## Объявить и вызвать параметризованный подсценарий

`@ExportScenarios` в тегах feature разрешает вызывать **все** сценарии этого файла. В вызывающем feature пишутся ключевое слово Gherkin и имя экспортного сценария.

```gherkin
# language: ru
@ExportScenarios
Функциональность: Подготовка строки

Сценарий: Я подготавливаю строку "Вход"
    И я запоминаю строку "Вход" в переменную "Значение"
    И я запоминаю строку "[Вход] — результат" в переменную "Описание"
```

В другом feature после подключения каталога экспортных сценариев:

```gherkin
И Я подготавливаю строку "пример"
Тогда переменная "Значение" имеет значение "пример"
```

Полный параметр шага должен точно совпадать с именем параметра в имени подсценария. Для встраивания в часть строки используется имя в квадратных скобках, как `[Вход]` выше. Это не синтаксис угловых параметров [структуры сценария](scenario-outlines.md). Сценарий без объявленных параметров не принимает обычные параметры только потому, что их дописали при вызове.

## Передать таблицы по позиции и сохранить остальные

Таблицы пишутся сразу после строки вызова; они заменяют таблицы у шагов внутри подсценария в порядке следования. Если аргумент не передан, остаётся таблица, объявленная внутри. Чтобы сохранить первую и заменить вторую, учебный пример использует пустую таблицу из двух вертикальных черт:

```gherkin
И Я вызываю подсценарий и передаю в него несколько таблиц
    ||

    | 'Другая таблица Gherkin 2' |
```

Это фрагмент вызова конкретного учебного экспортного сценария с несколькими табличными шагами, а не стандартный шаг для любой таблицы. Порядок аргументов — часть контракта: изменение порядка шагов в библиотеке может изменить место подстановки.

## Передать многострочный аргумент и предусмотреть default

Чтобы экспортный сценарий принял многострочный аргумент, в его теле должен быть шаг, принимающий многострочную строку. Имя сценария само по себе не объявляет такой параметр.

```gherkin
@ExportScenarios
Функциональность: Многострочное приветствие
Сценарий: Я вывожу многострочное приветствие
    И Я запоминаю в переменную "ТекстПриветствия" значение
    """
    Приветствие по умолчанию
    """
    И я вывожу сообщение в менеджер тестирования "$ТекстПриветствия$"
```

Вызов из другого feature:

```gherkin
И Я вывожу многострочное приветствие
    """
    Первая строка
    Вторая строка
    """
```

Без аргумента сработает строка по умолчанию. Несколько многострочных аргументов заменяются в порядке соответствующих шагов внутри сценария; не сопоставляйте их произвольно по имени.

## Сделать подсценарий доступным в поиске и удержать границу контекста

Для дерева известных шагов учебный пример задаёт теги сценария:

```gherkin
@типшага: МоиПодсценарии.Подготовка
@описание: Сохраняет переданную строку
@примериспользования: И Я подготавливаю строку "пример"
Сценарий: Я подготавливаю строку "Вход"
```

Группы типа разделяются точкой. Краткое описание и пример должны объяснять реальный эффект, предусловия и параметры, иначе переиспользование превращается в угадывание.

FAQ предлагает выносить составную проверку состояния документа в экспортный сценарий или собственный шаг, если она повторяется. При разных базах менеджера и клиента приведён подход через VAExtension и проверку полученного состояния объекта; запрос в контексте менеджера не проверяет автоматически объект клиентской базы. Изменение собственного кода шага — отдельная задача владельца библиотеки, не повод писать произвольный BSL в каждый UI-сценарий.
