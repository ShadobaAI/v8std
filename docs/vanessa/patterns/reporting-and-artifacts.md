# Отчёты и артефакты Vanessa: Allure, JSON, JUnit, скриншоты и логи

Справочная переработка текстов MainHelp 1.2.043.1, глава 02. Названия JSON-полей и элементы, видимые только на изображениях уроков, здесь не восстановлены. Рекомендации источника относятся к этой редакции и не определяют фактические настройки другого релиза.

## Различить сборки и выбрать формат

Имя сборки добавляется в начало имён сценариев, чтобы, например, тонкий и Web-запуски одного сценария отображались раздельно. Для этого включается соответствующий флаг и задаётся различающее имя каждой сессии. Статус сборки можно выгружать в явно указанный файл; перечень значений статуса дан во внутренней справке, в этом уроке он не приведён.

Для Cucumber и JUnit нужны флаг формирования и каталог. JUnit имеет опцию прикрепления скриншотов для GitLab. JSON предназначен для произвольных интеграций; внутренний формат — простейший локальный отчёт, не формат интеграции. СППР использует каталог, имя и версию тестируемой конфигурации; незаполненные имя/версия берутся из сеанса менеджера, что существенно при другой базе клиента.

## Сформировать Allure с нужной группировкой

Включите формирование Allure и задайте каталог. Альтернатива — общий каталог нескольких сборок: при добавлении имени сборки создаётся вложенный каталог с этим именем. Иерархия имеет три настраиваемых уровня и базовый каталог; подробный алгоритм уровней отсылает к F1. Настройка группировки влияет на вкладку suites.

Значения переменных можно подставлять вместо имён в текстах шагов; список исключений оставляет выбранные переменные без подстановки. Отдельный список тегов не выполняет помеченные сценарии и отражает их как пропущенные. Таблица дополнительных меток сопоставляет теги и метки регулярным выражением либо безусловно. Локальный отчёт открывается командой «Показать отчет Allure».

Источники: [урок 40][s40], [урок 39][s39], [урок 72][s72].

## Выбрать диагностические приложения и знать их происхождение

Allure может приложить журнал регистрации, сетевые соединения процессов, активную или все формы клиента на момент падения, список процессов, переменные, MXL, HTML, Excel и файлы различий эталонного/фактического макета. Журнал регистрации в этом механизме снимается на стороне менеджера тестирования, а не автоматически из базы клиента.

JSON отдельно настраивает сбор переменных, активной/всех форм, процессов и сетевых соединений. Наличие формата отчёта само по себе не включает все эти сведения. Для разового расследования команды сохранения текущей или всех форм экспортируют состояние в MXL.

Источники: [урок 41][s41], [урок 43][s43], [урок 72][s72].

## Получить скриншоты при ошибке и по тегу

Флаг скриншотов включает снимок при ошибке и перед шагом с тегом screenshot. Пустой каталог сохранения означает, что скриншоты сниматься не будут. Для CI справка рекомендует также снимки всех запущенных сеансов 1С. Режим VanessaExt и режим дополнительной утилиты имеют разные настройки: команда утилиты нужна во втором случае.

Для VanessaExt можно указать дополнительные приложения через точку с запятой с маской *; перечислять здесь процессы 1С не нужно. Для окон 1С рекомендован вариант «все окна клиента тестирования». Скриншот подключённого браузера требует его запуска с ключом отладки.

Источники: [урок 51][s51].

## Записать видео прохождения и события сессии

Видеозапись выполнения тестов требует флага, каталога, FPS и команды записи. Больший FPS увеличивает нагрузку на CPU; команду справка рекомендует оставить по умолчанию. Это артефакт прохождения, отдельный от генерации автоинструкции.

Лог событий пишет в файл и/или консоль начала сценариев, ошибки и, по отдельным опциям, каждый шаг и дополнительную статистику. Пустой путь отключает файл, сохраняя возможность консоли. Есть флаг сокрытия пароля подключения TestClient в логе. Сгенерированная командой Vanessa строка запуска с выводом в консоль снижает дисковую нагрузку согласно справке.
