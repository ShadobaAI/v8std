# Проверки формы, таблиц и MXL: имена, маски и эталоны

## Проверка наблюдаемого результата

Редактор умеет получать шаги по всей форме, шапке, текущему элементу, сообщениям, навигационной ссылке и текущему окну. Генерация всей формы создаёт исходный материал; полезная проверка отражает требование, а не случайные данные всех элементов. Текущий элемент должен быть активизирован до снятия его состояния.

Проверка шапки описана таблицей «элемент / значение / алгоритм поиска»; пустой алгоритм означает поиск по внутреннему имени. Имена и заголовки различаются. Команда редактора `Ctrl+J` заменяет способ поиска для установленного элемента при активном соответствующем окне TestClient; она не доказывает эквивалентность произвольных элементов.

## Видимость и доступность

Флаги `Видимость` и `Доступность` сами по себе не всегда отражают фактическую возможность действия: влияют родительская группа, функциональные опции и условное оформление. Проверка недоступности через ожидаемую ошибку действия требует предварительного доказательства существования элемента. Иначе отсутствие кнопки даст ложноположительный результат «нельзя нажать».

Проверки, меняющие поле ради проверки редактируемости, имеют побочные эффекты и требуют подходящей fixture. [Запись в произвольные существующие данные](test-data-strategies.md) не является нейтральной проверкой интерфейса.

## Таблица, макет и маски

| Механизм | Значение |
| --- | --- |
| Полная ячейка `*` | Исключение ячейки из поддерживающего это сравнения таблицы/макета |
| Часть значения с `*` | Нужен вариант шага «по шаблону»; обычное равенство этого не обещает |
| Табличный документ и MXL | Имя реквизита формы, basename эталона без расширения; поиск в корне проекта либо рядом с feature |
| Небольшой эталон | Gherkin-таблица удобна для читаемости |
| Большой эталон | Отдельный макет обычно читается и поддерживается лучше |

Маска поиска окна/элемента, маска сравнения значения и исключённая ячейка — разные механизмы. Расширенная маска может скрыть ошибку или выбрать другой объект.

## Динамический заголовок колонки

FAQ приводит приём: сохранить заголовок поля и подставить переменную в заголовок проверяемой Gherkin-таблицы. Синтаксис таблицы отличается от [табличных переменных](variables-and-parameters.md).

```gherkin
И я запоминаю заголовок поля с именем "РеквизитСтрока" как "ЗаголовокКолонки"
Тогда таблица 'Список' стала равной:
    | 'Наименование' | '$ЗаголовокКолонки$' |
    | 'Тестовый элемент' | '' |
```

Это адаптированный пример FAQ с учебными именами. Для реального окна требуются реальные имена и установленный стандартный шаг.

## Типичные ошибки

Выбор «по номеру» и выбор по представлению различаются; в описанном механизме номер передаётся числом без кавычек. Визуально похожие «меню» и «список выбора» также имеют разные шаги. Окна с одинаковым заголовком требуют различимого целевого окна; наличие двух совпадений не подтверждает уникальность.
