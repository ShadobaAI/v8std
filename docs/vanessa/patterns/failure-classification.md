# Классы сбоев UI-теста: тест, продукт, данные, инфраструктура

## Как различаются причины

| Класс | Признак | Что это означает для результата |
| --- | --- | --- |
| Устаревший UI-тест | Имя элемента или навигация изменились, требуемое поведение сохранилось | Исправление локатора отличается от изменения ожидания |
| Дефект продукта | Наблюдаемое поведение нарушает ожидаемый результат | Ослабление assertion не исправляет продукт |
| Данные/права | Подготовка не соответствует fixture, роли или исходному состоянию | Это не успешная проверка функции |
| Инфраструктура | Не тот runtime, база, TestClient, расширение или незавершённый запуск | Доступность HTTP сама по себе не подтверждает UI-готовность |
| Неверный вызов | Параметры не соответствуют текущей MCP-схеме | Документированная карточка другой версии не заменяет схему |
| Неопределённый исход | Timeout/обрыв после отправки изменяющего вызова | Отсутствие ответа не доказывает отсутствие действия |

## Доказательства относятся к одному исполнению

Полезны точный feature и сценарий, версия текста, ожидаемое/фактическое состояние, сообщение ошибки, выполненные шаги и версия runtime. Данные предыдущего прогона с тем же именем не доказывают исход текущего.

Техническая возможность редактора актуализировать эталон не определяет, какой результат правильный. Пауза и повтор без изменения причины не объясняют исходный сбой.

Порядок действий агента, полномочия на изменение данных и условия продолжения находятся в навыке и инструкциях проекта. Этот рецепт задаёт различия причин, а не обязательный процесс согласования.
