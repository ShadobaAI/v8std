# Повторить сценарий с разными данными: Структура сценария и Примеры

Основание: MainHelp 1.2.043.1, секция «Структура сценария», и соответствующий учебный feature. Синтаксис ниже документирован; выбор наборов данных и проверок — рекомендация. Наличие конструкции в справке не подтверждает библиотеку шагов установленного runtime.

## Выбрать структуру вместо копий сценария

Используйте `Структура сценария:`, когда последовательность действий и смысл проверки одинаковы, а значения различаются. Каждый набор примеров даёт отдельное выполнение этой последовательности. Если различаются существенные ветви поведения и критерии успеха, отдельные именованные сценарии обычно понятнее.

Внутри шагов используются параметры в угловых скобках. После всех шагов обязательны `Примеры:` и таблица минимум из двух строк: первая перечисляет имена параметров, остальные — конкретные наборы значений.

## Задать вход и ожидание отдельными колонками

Пример адаптирует структуру учебного feature к существующим шагам строковых переменных:

```gherkin
# language: ru
Функциональность: Параметризация строк

Структура сценария: Строка сохраняется без изменения
    И я запоминаю строку <Вход> в переменную "Результат"
    Тогда переменная "Результат" имеет значение <Ожидание>

    Примеры:
        | 'Вход'   | 'Ожидание' |
        | 'Альфа'  | 'Альфа'    |
        | 'Бета'   | 'Бета'     |
```

Угловые скобки в этом блоке — синтаксис Turbo Gherkin, а не произвольное обозначение placeholder. Имена колонок должны соответствовать параметрам шагов. Две строки данных в примере означают два выполнения сценария; заголовок не является набором данных.

Значения в учебной таблице заключены в апострофы. Не заменяйте таблицу `Примеры` таблицей аргумента одного шага или таблицей секции `Переменные`: у них разные назначения.

## Сохранить независимость вариантов

Контекст feature выполняется перед каждым сценарием; подготовка должна обеспечивать воспроизводимый запуск каждого варианта, а не рассчитывать на предыдущую строку. Общая глобальная переменная или оставшиеся записи базы способны связать варианты и скрыть ошибку. См. [переменные и параметры](variables-and-parameters.md) и [данные сценария](test-data-strategies.md).

Для каждого набора сохраняйте исходный смысл assertions. Не вычисляйте ожидаемое значение тем же действием, которое тестируется, только чтобы избежать отдельной колонки ожидания.

## Результаты отдельных примеров

Каждая строка данных задаёт отдельное выполнение. Успешный результат одной строки не доказывает выполнения остальных; частичный запуск со строки охватывает только выбранный фрагмент. Проверка синтаксиса и результаты выполнения отвечают на разные вопросы. См. [запуск и диагностика](execution-debugging.md).
