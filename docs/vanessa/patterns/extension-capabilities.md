# Выбрать возможности VAExtension в базе клиента тестирования

Основание — текущий snapshot документа `VAExtension.md`, где перечислены 37 возможностей. У документа нет собственной маркировки релизом: это обзор документированных механизмов, не подтверждение их наличия в любой установленной CFE. Точные шаги найдите в библиотеке runtime, для MCP проверьте текущий `tools/list`. Установка/обновление расширения — отдельная операция.

## Отличить расширение клиента от компоненты менеджера

VAExtension устанавливается в базу, где работает **клиент тестирования**. Его шаги позволяют получить данные и выполнить действия именно там, в том числе когда менеджер находится в другой базе. Это не внешняя компонента VanessaExt и не MCP-расширение менеджера: [подключаемые компоненты](external-components.md).

| Задача | Возможности из документа | Что проверить |
| --- | --- | --- |
| Дождаться готовности | Ожидание фоновых заданий клиента | Нужную базу и фактическое завершение, а не паузу |
| Узнать состояние формы | Навигационная ссылка, значения реквизитов, модифицированность, ТолькоПросмотр | Текущее окно и ожидаемое значение |
| Узнать состояние объекта | Текущий объект либо объект по навигационной ссылке | Правильный объект и явную проверку полученных переменных |
| Сравнить отчёт | Получение макета без временных файлов, в том числе Web; сравнение варианта с эталоном | Имя метаданных отчёта и пользовательское имя варианта |
| Проверить окружение клиента | Подключённые расширения, интерфейс, файловая/серверная база, версия подсистемы | Версию/активность именно нужного клиента |
| Пройти нестандартный UI | Гиперссылка HTML, открытие файла как пользователем, UI Automation ID | Имена/представления и побочные эффекты |
| Эмулировать интеграцию | Сканер, внешние события, каталог файлов событий | Подготовленный канал и результат события |

## Получить состояние и отдельно утверждать результат

```gherkin
И Я жду завершения выполнения всех фоновых заданий в течение 100 секунд (Расширение)
И я получаю состояние текущего объекта (Расширение)
```

Для открытого справочника/документа документируетcя создание переменных состояния. Для чтения без привязки к открытой форме:

```gherkin
И я получаю состояние объекта по навигационной ссылке "НавСсылка" (расширение)
```

У шага по ссылке перечислены `ТипЭлемента`, `ПометкаУдаления`, `Проведен`, `Дата`, `Номер`, `Код`; применимость отдельных реквизитов зависит от типа объекта. Успешное чтение не означает, что документ проведён или значение равно ожидаемому: используйте подходящий проверяющий шаг и корректный тип переменной.

`И я вывожу данные текущего окна (Расширение)` создаёт печатную форму в менеджере; источник рекомендует его для отладки и прямо не рекомендует оставлять в реальных сценариях.

## Передать ссылку между разными базами осмысленно

Документ различает объектную ссылку для одной базы и строковое представление для разных баз:

```gherkin
И я сохраняю строковое представление ссылки на объект из текущего окна в переменную "Ссылка"
И я открываю объект по строковому представлению ссылки "Ссылка" (расширение)
```

Это описанный контракт шагов, а не обещание, что одинаковый идентификатор существует в произвольной другой базе. Перед открытием установите происхождение ссылки и данные целевой базы. См. [стратегии данных](test-data-strategies.md).

## Не спутать чтение с программным изменением поведения

Возможности выполнения кода/метода формы, изменения реквизита, сортировки списка, ограничения типа поля, проведения/отмены проведения, очистки табличного документа и пометки удаления меняют приложение или данные. Выбирайте их только если это соответствует проверяемой границе теста. Подмена пользовательского действия программной записью способна обойти именно проверяемую бизнес-логику.

Шаги получения UI Automation ID временно меняют подсказку элемента для его поиска, затем восстанавливают её. Шаги отключения обновления текста редактирования меняют свойство полей, чтобы избежать отката ввода после серверного вызова; это изменение поведения формы, а не нейтральное чтение. Не добавляйте его для маскировки неизвестной причины сбоя.

`LinksToDelete` накапливает навигационные ссылки, а отдельный шаг устанавливает пометку удаления. Это не автоматическая очистка и не безвозвратное удаление. Для своего теста определите точные объекты и план сохранения состояния.

## Передать внешнее событие и дождаться ответа

Механизм файлов событий требует предварительного запуска мониторинга каталога **в тестируемом приложении**. После обработки создаётся файл-ответ; шаг ожидания получает результат.

```gherkin
И я запускаю мониторинг каталога "EVENTS_DIR" для внешних событий(Расширение)
И я вызываю внешнее событие "Источник" с событием "Событие" с данными "Данные" через файл события (Расширение)
И я ожидаю "10" секунд результат обработки последнего события через файл и запоминаю результат в переменную "Ответ"(Расширение)
И я останавливаю мониторинг каталога внешних событий(Расширение)
```

`EVENTS_DIR` — подготовленный каталог профиля, не литерал для копирования без настройки. Документ описывает выполнение файловых команд даже при модальном/блокирующем окне. Это возможность канала, а не основание обходить неизвестный диалог. Сканирование добавляет нагрузку; в источнике отмечена задержка обработки до секунды. Таймаут отправки требует проверки результата, а не слепого повторения события.

## Получить фактическую версию, интерфейс и журнал

Документ включает получение списка расширений в переменные `Extension_ИмяРасширения` со свойствами `Name`, `Synonym`, `UID`, `Version`, `SafeMode`, `Active`; чтение интерфейса возвращает `Версия8_2`, `Такси`, `Версия8_5` или английские варианты. Это проверяемые значения окружения, не универсальное требование выбрать один интерфейс.

Возможность 37 обслуживает MCP `get_event_log_test_client`: журнал читается в базе клиента, фильтруется и обрезается до передачи компактного JSON. Отдельного Gherkin-шага у неё нет. Чтение выполняется привилегированно независимо от прав клиента, поэтому успешный ответ не доказывает наличие у тестового пользователя бизнес-прав. Выбирайте релевантный период/фильтры/бюджет по фактической схеме MCP.
