# Ожидания состояния формы, асинхронные шаги и паузы

## Возврат управления не равен завершению действия

Отложенное проведение, обработчик ожидания, открытие формы и заполнение отчёта могут продолжаться после возврата управления сценарию. Следующий шаг, рассчитанный на готовые данные, в таком случае попадает в гонку.

Наблюдаемое условие завершения — закрытие нужного окна, появление требуемого окна, готовность отчёта или проверяемое состояние элемента — позволяет ограничить ожидание и продолжить раньше предела. Наличие такого ожидания не заменяет итоговую проверку результата операции.

## Как выбирать ожидание

| Ситуация | Подход |
| --- | --- |
| Известно состояние готовности | Соответствующий стандартный шаг ожидания с конечным пределом |
| Фоновые задания клиента | Механизм ожидания VAExtension в базе TestClient |
| Изменение интерфейса вне testing API | Проверяемое UI-состояние или поддерживаемое ожидание внешнего интерфейса |
| Наблюдаемого события нет | Обоснованная короткая пауза; её длительность остаётся ограничением теста |

Точные сигнатуры ожиданий зависят от установленной библиотеки. В уроках часть примеров представлена только изображениями; озвученное название не является полной сигнатурой Gherkin.

## Почему «5 секунд» могут закончиться через 10

Урок версии 1.2.043.1 объясняет взаимодействие явно заданного ожидания и общей настройки «Таймаут для асинхронных шагов» в «Выполнение сценариев → Стабилизация выполнения сценариев». В примере общий предел 10 секунд влияет на шаг с ожиданием 5 секунд. Это пример настройки той редакции, а не универсальное обещание точного времени выполнения.

Большие фиксированные паузы увеличивают время каждого прогона и не доказывают готовность на медленном агенте. Отдельная скорость проигрывания сценария также не превращает шаг в проверку состояния.
