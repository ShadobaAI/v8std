# Клиенты тестирования: таблица подключений, порты, Web и параметры запуска

Справочная переработка текстов MainHelp 1.2.043.1, глава 02. Названия JSON-полей и элементы, видимые только на изображениях уроков, здесь не восстановлены. Рекомендации источника относятся к этой редакции и не определяют фактические настройки другого релиза.

## Выбрать строку подключения, а не базу менеджера по умолчанию

Строка таблицы описывает конкретное подключение. Таблицу заполняют вручную, из сценария либо через JSON при командном запуске. Первая служебная строка всегда соответствует базе менеджера Vanessa. Быстрое подключение Ctrl+T использует активную строку таблицы; если строку не меняли, это обычно служебная строка.

Имя подключения уникально в таблице. Поиск шагами сначала идёт по колонке «Имя», затем по «Синониму». Синоним полезен при работе с СППР, где имя генерируется автоматически. Типы: тонкий и толстый на управляемых формах, Web, обычное приложение, мобильный клиент, мобильное приложение. Путь — файловая база или серверная строка для тонкого/толстого, URL для Web. Построчные дополнительные параметры содержат ключи подключения.

Источники: [урок 52][s52], [урок 53][s53], [урок 54][s54], [урок 67][s67].

## Различить новый процесс и уже работающий клиент

Для тонкого/толстого клиента колонка компьютера указывает машину запуска или уже работающего клиента. При локальном запуске руководство задаёт localhost. Для нового клиента в порте допускается свободный порт либо значение 1: Vanessa проверяет доступность и выбирает свободный порт. Для подключения к уже работающему клиенту нужен его фактический порт; неверный порт не подключит этот клиент.

Уникальность тонкого/толстого TestClient определяется портом, другие поля не учитываются. При новом запуске с VanessaExt заполняется PID. Общая настройка диапазона ограничивает выбор портов; без диапазона свободный порт выбирается начиная с 48100. Число 48100 — поведение данной редакции справки, а не обязательный порт любого профиля.

Источники: [урок 55][s55], [урок 25][s25].

## Управлять запуском и расследовать неподключение

Развёрнутое окно рекомендовано для более полных скриншотов. Отдельный флаг определяет, считать ли модальное окно при запуске ошибкой. Если процесс не найден, например из-за лицензии, настраиваемая опция повторяет запуск через заданный интервал; справка предлагает её при наблюдаемой проблеме первого запуска. Таймаут подключения вызывает исключение, если клиент не подключился вовремя. Дополнительное определение порта Linux включается только при фактическом запуске на другом порту.

Общие дополнительные параметры добавляются к построчным параметрам при каждом запуске. Есть вывод служебных сообщений в файл для каждого клиента, запрет более одного TestClient, отключение фактического запуска регламентных заданий файловой базы и контроль серверных вызовов в обработчиках событий. Эти опции решают разные задачи; запрет нескольких клиентов, например, полезен при ограниченной памяти.

Опция контроля закрытия ждёт заданное число секунд; если клиент штатно не закрылся, его процесс снимается средствами ОС. Это реальный эффект настройки.

Источники: [урок 25][s25], [урок 23][s23].

## Подключить Web и корректно завершить его сеанс

Для файловой базы Web: компьютер localhost, порт локального web-сервера; в уроке обычный пример — 1538. Для серверной базы: сетевое имя или IP кластера, порт кластера (обычно 1541) и доступ менеджера по сети к менеджеру кластера. Web-клиент уникален по имени подключения.

Закрытие вкладки или браузера может оставить сеанс на сервере. Справка описывает корректный выход через «Файл → Выход» либо эквивалентное завершение сеанса.

Пустая команда браузера запускает браузер по умолчанию. Для другого браузера или ключей указывается команда. Две команды заполнения Chrome создают обычный запуск либо запуск со специальными ключами для автодокументации. Режим работы Chrome через специальный порт нужен для прямой работы со страницами и анимации действий в автоинструкциях.

Источники: [урок 56][s56], [урок 24][s24].

## Отладчик, Android и сохранение списка

Флаг подключения клиента к отладчику открывает адрес отладчика и дополнительные ключи. Для Android указывается путь к adb, после чего доступны проверка подключения к устройству, запуск мобильного клиента и приложения.

Список клиентов сохраняют отдельной командой в пользовательских настройках текущей базы либо переносят вместе с остальными настройками через JSON. Формат отдельной загрузки можно получить экспортом настроек; названия JSON-полей в этих уроках текстом не раскрыты.

Источники: [урок 27][s27], [урок 26][s26], [урок 81][s81], [урок 1][s1].
