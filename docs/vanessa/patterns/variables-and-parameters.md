# Передать и проверить значения: переменные, таблицы, типы и экранирование

Основание: MainHelp 1.2.043.1, главы 03/06 и учебные feature. Формы подстановок описывают эту редакцию; наличие шага и настройку вычислений проверяйте в своей версии. Примеры кода ниже поясняют контекст, а не разрешают выполнять произвольные изменения базы.

## Выбрать область жизни и не связать независимые тесты

Локальная переменная живёт в сценарии и очищается при его завершении. В шагах имя создаваемой локальной переменной обычное, а передача значения использует доллары. Глобальная живёт, пока открыта форма Vanessa; её имя при создании и подстановке обрамляется двойными долларами.

```gherkin
И я запоминаю строку "готово" в переменную "Локальная"
Тогда переменная "Локальная" имеет значение "готово"
И я запоминаю строку "готово" в переменную "$$ОбщееЗначение$$"
Тогда переменная "Локальная" имеет значение "$$ОбщееЗначение$$"
```

Перед переиспользованием глобальной переменной установите исходное значение. Для удаления предусмотрены шаг по имени, `И я удаляю все локальные переменные`, `И я удаляю все глобальные переменные`, `И я удаляю все переменные`. Массовая очистка затрагивает общий контекст — применяйте её только в принадлежащем тесту окружении.

Табло переменных показывает и позволяет менять значения, а также предлагает шаг проверки. Значение в правой части выполненного шага и tooltip полезны для диагностики; ручная правка табло не должна скрывать отсутствие подготовки в сценарии.

## Сохранить тип и подставить часть строки

Параметры/простые значения в документации представлены строкой, числом и датой. Строка — рекомендуемый основной тип; числовой/дата нужны по смыслу задачи. Число пишется без кавычек, например `0.1` или `-0.123`; примеры даты — `08.04.81` и `08.04.1981`. Строки заключаются в кавычки или апострофы.

```gherkin
И Я запоминаю значение выражения '1+1' в переменную "Сумма"
И Я запоминаю значение выражения 'Строка(1+1)' в переменную "СуммаКакСтрока"
И Я запоминаю значение выражения 'ТекущаяДата()' в переменную "Момент"
И я запоминаю строку "А" в переменную "Первая"
И я запоминаю строку "Б" в переменную "Вторая"
И я запоминаю строку "$Первая$ $Вторая$" в переменную "Строка"
```

Подстановка нескольких переменных внутрь одного строкового параметра документирована только для строковых переменных. Для строк можно сравнить шагом `Тогда переменная "Первая" имеет значение "$Вторая$"`; для других типов учебник показывает выражение через `Контекст`. Условия сами по себе не являются утверждением результата: [условия и исключения](conditions-loops-exceptions.md).

## Объявить Переменные и импорт без исполняемых setup-шагов

Значения секции `Переменные:` инициализируются перед каждым сценарием feature. Поддерживаются простые, многострочные значения и выражения в фигурных скобках. Выражение без `!` вычисляется на клиенте менеджера тестирования, с `!` — на его сервере, **не в клиенте тестирования**.

```gherkin
Переменные:
    Метка = "готово"
    Вычислено = "{Строка(1+1)}"
    НаСервере = "{!Строка(1+1)}"
    Описание = "Метка={Метка}"
    Импорт "ОбщиеПеременные.feature"
```

Импортируемый feature должен реально существовать и объявлять нужные переменные. Для значений секции в учебнике допускается обращение без долларов, встраивание в строку использует фигурные скобки. Не смешивайте это с именами параметров [подсценария](subscenarios-and-libraries.md).

Служебные `$КаталогПроекта$`, `$КаталогИнструментов$`, `$КаталогФичи$` берут значения из настроек проекта, каталога Vanessa и каталога текущего feature; это средство избежать фиксированных машинных путей, а не подтверждение существования файла.

## Отличить таблицу Переменные от обычной таблицы шага

В секции может быть одна таблица без имени и несколько именованных; перед именем стоит `*`. Нужны заголовок и хотя бы одна строка данных. Первая колонка задаёт ключ строки.

```gherkin
Переменные:
    * Набор
        | 'Ключ'   | 'Значение' |
        | 'Первый' | 'А'        |
        | 'Второй' | 'Б'        |

Сценарий: Чтение строки таблицы
    И я вывожу значение переменной "Набор.Первый.Значение"
```

Обращение к безымянной таблице: имя строки, затем колонка через точку; к именованной: имя таблицы, строки, колонки. Заголовки и ключи строк таблицы переменных должны быть корректными идентификаторами 1С: буквы/цифры/подчёркивание, первый символ — буква либо подчёркивание. Пробел в заголовке может дать «Задано неправильное имя атрибута структуры».

Таблица переменных реализована структурой с ключами, обычная Gherkin-таблица шага — массивом строк; обе не являются ТаблицейЗначений. Не переносите индексный доступ или цикл «по таблице в памяти» на именованную таблицу: [выбор цикла](conditions-loops-exceptions.md).

## Передать значение выражению и сохранить границу сервера

При текстовой подстановке `$Имя$` в выражение нужно самостоятельно сохранять тип и кавычки. Учебник даёт альтернативу: локальные значения через `Контекст.Имя`, глобальные через `КонтекстСохраняемый.Имя` на клиентской стороне менеджера. Создание кодом использует `Контекст.Вставить(...)` / `КонтекстСохраняемый.Вставить(...)`.

Параметр подсценария можно сохранить обычным строковым шагом, если его параметр точно совпадает с объявленным именем. Для выражения на сервере предпочтительны существующие шаги «с передачей переменных». В справке также показаны старые варианты с экранированием текста и промежуточным реквизитом; не заменяйте ими текущий шаг без причины. Повторяемый сложный код лучше оформить отдельным шагом владельца библиотеки.

## Экранировать Gherkin, а не командную строку платформы

В параметрах Gherkin кавычка экранируется обратной косой чертой; апостроф имеет приоритет, поэтому двойную кавычку внутри апострофов можно не экранировать. Апостроф внутри параметра требует экранирования и при внешних кавычках, и при внешних апострофах.

```gherkin
Дано пример кавычка внутри кавычки "Часть1 \" Часть2"
Дано пример кавычка внутри апострофов без экранирования 'Часть1 " Часть2'
Дано пример апостроф внутри кавычек "Часть1 \' Часть2"
Дано пример шага, в который передаётся таблица Gherkin
    | 'Часть1 \| Часть2' |
```

Последний блок показывает синтаксис учебных демонстрационных шагов, не обещает их наличия в библиотеке. В ячейках `\|` передаёт вертикальную черту, `\n` — перевод строки. Одна обратная черта сохраняется; две последовательные интерпретируются как одна. Фигурные скобки экранируются при включённой настройке вычисления выражений; при выключенной это не требуется. Не переносите эти правила на `/IBConnectionString`: [запуск платформы](environment-readiness.md) использует свои правила кавычек.

## Передать GlobalVars без угадывания схемы

В [описании параметров GlobalVars](https://github.com/Pr-Mex/vanessa-automation/blob/develop/docs/JsonParams/JsonParamsRU.md) явно задана Структура пар ключ/значение, попадающих в `КонтекстСохраняемый`. Учебный feature согласуется с этим определением: секция представлена JSON-объектом.

```json
{
  "GlobalVars": {
    "ОбщееЗначение": "готово"
  }
}
```

Слово «массив» в тексте отдельного урока — неточное общее обозначение, а не альтернативная схема JSON. При обновлении runtime сверяйте его формат VAParams и фактическое чтение значения; не преобразуйте объект в JSON-массив по этой формулировке. Пароли и данные конкретной базы не принадлежат общему corpus.
