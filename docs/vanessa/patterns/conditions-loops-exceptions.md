# Выбрать условие, цикл или обработку ошибки без потери assertions

Основание: MainHelp 1.2.043.1 и учебные feature условий/циклов/исключений. Это описания Turbo Gherkin этой редакции; применимость конкретных шагов определяется подключённой библиотекой. Документация рекомендует избегать конструкций, если сценарий можно ясно записать без них.

## Разветвить разрешённое поведение, не спрятать дефект

Условие начинается с `Если` и заканчивается `Тогда`; тело имеет дополнительный отступ. Поддерживаются `ИначеЕсли` и `Иначе` на уровне исходного условия.

```gherkin
Если в таблице "ИмяТаблицы" количество строк "равно" 0 Тогда
    // Разрешённая обработка пустой таблицы
ИначеЕсли в таблице "ИмяТаблицы" количество строк "равно" 1 Тогда
    // Разрешённая обработка одной строки
Иначе
    // Разрешённая обработка остальных случаев
```

Это синтаксическая схема на шаге учебной библиотеки, не проверка конкретной формы. Реальные имена и действия нужны из исследованного UI. Исторически выделенные шаги-условия помечены в дереве зелёным; документация также разрешает обернуть обычный шаг в `Если ... Тогда`: исключение при его выполнении даёт Ложь, отсутствие исключения — Истину.

Поэтому не помещайте обязательную проверку результата в условие только ради продолжения: ошибка может превратиться в невыполненную ветвь. Итоговое ожидание должно оставаться проверяющим шагом, а не исчезать при ложном условии.

## Выбрать цикл и ограничить работу

Циклический шаг может начинаться с любого ключевого слова Gherkin. Вложенные шаги отделяются отступом; специальные циклические шаги помечены фиолетовым в дереве библиотеки.

```gherkin
Затем я делаю 10 раз
    // Тело повторения

И пока выражение встроенного языка 'УсловиеНаВстроенномЯзыке' истинно я выполняю
    Тогда я прерываю цикл
```

Второй фрагмент — схема, где выражение нужно заменить доказанным условием; не исполняйте несуществующий идентификатор. `Тогда я продолжаю цикл` аналогичен продолжению итерации, `Тогда я прерываю цикл` завершает цикл. У цикла должен быть проверяемый смысл, предел либо условие завершения; бесконечный повтор не исправляет инфраструктуру.

## Перебрать именованную таблицу Переменные

Для таблицы секции `Переменные` нужен шаг `И для каждой строки таблицы "ИмяТаблицы" я выполняю`. На каждой итерации создаются переменные с именами колонок и значениями текущей строки:

```gherkin
Переменные:
    * Приветствия
        | 'Язык'       | 'Приветствие'  |
        | 'Русский'    | 'Привет, мир!' |
        | 'Английский' | 'Hello!'       |

Сценарий: Обход именованной таблицы
    И для каждой строки таблицы "Приветствия" я выполняю
        И я вывожу сообщение в менеджер тестирования "$Язык$: $Приветствие$"
```

Это не `И для каждого значения "Строка" из таблицы в памяти "МояТаблица"`: FAQ специально различает обычную таблицу шага и структуру таблицы переменных. Проверяйте допустимость идентификаторов колонок/ключей: [переменные и таблицы](variables-and-parameters.md).

## Обработать исключение и сохранить ошибку в результате

`Попытка` и `Исключение` обязательны; тела обоих блоков с дополнительным отступом. Ошибка внутри попытки передаёт управление в обработчик, не обязательно останавливая сценарий.

```gherkin
Попытка
    И в таблице "ИмяТаблицы" я перехожу к строке
        | 'ИмяКолонки'      |
        | 'ЗначениеКолонки' |
Исключение
    И я регистрирую ошибку "В таблице нет нужной строки" по данным исключения
```

Шаг регистрации по данным исключения допускается только в `Исключение`. Он позволяет собрать несколько ошибок за один сценарий. Пустой обработчик или закрытие окна без регистрации не должны превращать невыполненное ожидание в passed. Не копируйте из демонстрационного примера закрытие клиентского сеанса как универсальную очистку.

## Разобраться с ожиданием и таймаутом

FAQ объясняет, почему шаг «в течение 5 секунд» может завершиться через 10: на поведение влияет общая настройка «Таймаут для асинхронных шагов» в «Выполнение сценариев → Стабилизация выполнения сценариев»; в описанной версии default — 10 секунд. Не считайте число в тексте шага доказанным общим пределом и не меняйте глобальный timeout ради маскировки дефекта. Подтвердите фактическую настройку и состояние операции.
