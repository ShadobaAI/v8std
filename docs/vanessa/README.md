# База знаний Vanessa Automation

В коллекции 39 компактных patterns и 47 карточек MCP. Точка входа —
`vanessa:patterns:catalog`: карта задач со связями между рецептами. Прежние восемь
ID сохранены. Содержание переработано по задачам, а не скопировано из уроков.

## Поиск и чтение

`v8std_search` с `collections=["vanessa"]` ищет по русским вопросам, терминам,
aliases, заголовкам и тексту. Для выбора рецептов можно уточнить `types=["pattern"]`.
Примеры запросов: «структура папок UI тестов», «экспортный сценарий общие шаги»,
«подготовка данных повторный запуск», «CI локально проходит», «таймаут асинхронного
шага», «выбор файла веб клиент».

`v8std_get_page` возвращает целую страницу по canonical ID; для полного pattern
достаточно `body_limit=12000`. При усечении используется известная секция через
`v8std_get_section`. Семантические H2 делят условия, варианты, примеры и ограничения.
Относительные ссылки образуют `related` между знаниями. Специализированные
`get_pattern/get_api_card` остаются инструментами YAxUnit; Vanessa использует
общие search/page/section. Прежние коллекции `v8std`, `corporate`, `yaxunit` сохранены.

## Что входит

- Структура каталогов, секции feature, Примеры, теги, библиотеки, переменные,
  условия, циклы и исключения.
- Подготовка и повторяемость данных, smoke-генерация, проверки форм и MXL,
  ожидания, паузы и файловые диалоги.
- Профили клиентов, настройки, VAParams/CI, исполнение, отчёты, диагностика,
  VanessaExt/VAExtension, встроенный код и разные базы.
- Web/UI Automation, мобильные режимы, почта, видео/TTS, интерактивная справка,
  onboarding, Single и собственные шаги.

`source-map.json` классифицирует 579 исходников: текущие главы MainHelp
1.2.043.1, тематические страницы и цитируемые Gherkin-примеры, исторические версии,
перевод, release history и инструкции конкретных AI-примеров. Все 175 Markdown
текущего руководства отражены в карте. Три урока только отсылают к видео; детали
из видео и сигнатуры только на изображениях не считаются извлечёнными знаниями.
Границы указаны в самих рецептах. Имена каталогов прикладной схемы не выдаются
за обязательный стандарт Vanessa, а ERP/DT-restore/запрет Контекста из отдельных
примеров не становятся общими правилами.

## Разделение с навыком

В v8std находятся справочные факты, синтаксис, условия применения, альтернативы,
ограничения версии и происхождение. Навык `vanessa-ui-tests` определяет действия
ИИ: выбор релевантной справки, проверку текущего runtime, управление цепочкой
исполнения и подтверждение результата. Настройки конкретной базы и соглашения
тестов принадлежат профилю/проекту. Содержимое инструкций агента не дублируется
в справочном корпусе.

## Обновление и проверка

Из корня v8std:

```text
python scripts/sync_vanessa_docs.py --upstream VANESSA_SOURCE --devkit DEVKIT_SOURCE
python scripts/sync_vanessa_docs.py --upstream VANESSA_SOURCE --devkit DEVKIT_SOURCE --check
python -m unittest tests.test_vanessa_collections tests.test_vanessa_retrieval_quality tests.test_knowledge_collections tests.test_mcp_container_contract
```

Новые источники сначала классифицируются в source-map и перерабатываются в
рецепты. Sync обнаруживает неучтённый/пропавший источник, неизвестный pattern,
потерю прежних ID и drift. Он не копирует руководство целиком. Generator v2
фиксирует hashes входов, карты, документов и LICENSE. Reader поддерживает
snapshot v1/v2. Для архивов Git revision остаётся null; content_revision — SHA-256,
а не выдуманный commit. `complete` означает полноту объявленного реестра и таблицы
MCP, не полноту внешних медиа, схем runtime или любого будущего выпуска.

Сборка проверяет snapshot без upstream. Docker-образ содержит готовый индекс,
manifest, source-map и лицензию. При старте синхронизация/генерация не выполняются,
для ежедневной работы checkout и сайт Vanessa не нужны.
