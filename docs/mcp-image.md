# Самодостаточный образ v8std MCP

Образ `v8std-mcp:latest` содержит MCP-сервер и сформированные
при сборке `pages.jsonl`, `search-vectors.jsonl`, `llms.txt` и `llms-full.txt`.
Контейнер не требует checkout репозитория, volume или генерации при старте.
В индекс включены локальные `docs/corporate`, `docs/yaxunit` и `docs/vanessa`, в том числе
непубличные корпоративные правила. Публикуй такой образ только для тех, кому
предназначен этот корпус. Сайт в образ не устанавливается.

## Изменения upstream и собственные документы

Runtime перенесён в `runtime/`; зависимости берутся из lock-файлов upstream.
Сохранены фильтры коллекций и компактные методы fork. Самодостаточный образ
использует поддерживаемые upstream параметры `--pages` и `--vectors`: локальные
данные не заменяются публичным snapshot при запуске или обновлении.

Готовый `ghcr.io/zeegin/v8std-mcp:stable` по умолчанию скачивает публичный snapshot.
Он также поддерживает подключение готовых JSONL через volume и параметры
`--pages` и `--vectors`, но не преобразует Markdown и не содержит методы fork.
Поэтому для полного сохранения `corporate`, `yaxunit` и `vanessa` используй `Dockerfile.mcp`.
Добавляй документы в соответствующие каталоги с метаданными по их README,
затем пересобирай образ. Пересборка включает актуальный корпус целиком.

Общий алгоритм разбиения векторов оставлен upstream: это обеспечивает совместимость
с его snapshots. Метаданные коллекций, уровней и тегов остаются в текстовом поиске.

## Локальная сборка

Запустите:

```cmd
build-v8std-mcp.cmd
```

Скрипт выполняет `docker build --no-cache -f Dockerfile.mcp`, поэтому все
артефакты создаются заново. Образ получает один готовый для публикации тег
`<docker-hub-namespace>/v8std-mcp:latest`. Namespace
автоматически определяется из учетных данных `docker login`. Его можно явно
переопределить переменной окружения `V8STD_MCP_DOCKER_USER`. Автоматической
публикации нет.

При необходимости опубликуйте образ вручную:

```cmd
docker login
build-v8std-mcp.cmd
docker push <docker-hub-namespace>/v8std-mcp:latest
```

## Запуск сотрудником

Убедитесь, что образ уже загружен локально, и запустите контейнер:

```cmd
docker run --name v8std --restart unless-stopped -p 127.0.0.1:8766:8766 -d <docker-hub-namespace>/v8std-mcp:latest
```

В Windows собранный образ запускается с его полным тегом:

```cmd
run-v8std-mcp.cmd <docker-hub-namespace>/v8std-mcp:latest
```

Без аргументов скрипт по-прежнему использует локальный образ `v8std-mcp:latest`, но
`build-v8std-mcp.cmd` этот дополнительный тег не создает.
Скрипт не выполняет `docker pull`; обновление образа выполняется вручную:

```cmd
docker pull <docker-hub-namespace>/v8std-mcp:latest
```

После запуска MCP доступен по адресу `http://127.0.0.1:8766/mcp`.

Корпус [Vanessa](vanessa/README.md) синхронизируется явно до сборки. Образ включает готовые документы в индексе, manifest, source-map и BSD-3-Clause license. Сборка проверяет полноту и хеши без upstream checkout. Синхронизация и генерация при старте не выполняются. Обновление работающего контейнера — отдельная операция.


## Навигация по знаниям через MCP

Ответы всех 11 инструментов используют ссылки вида `v8std:std437` и
`v8std:vanessa:patterns:project-layout`. Передайте такую ссылку целиком в
`v8std_get_page`, `v8std_get_section` или другой инструмент чтения; открывать
сайт для получения текста не требуется. Сохраняются canonical ID, секции и связи.
Если ссылка неоднозначна, `reference_candidates` перечисляет существующие
материалы для выбора, без произвольного первого совпадения.

В выдаче MCP нет полей `url`, `markdown_url`, `source_urls`. Известные ссылки
в тексте преобразуются во внутренние ссылки корпуса; у внешних источников
сохраняются названия. URL в примерах кода остаются буквальными данными.
Происхождение, полные тексты и хеши источников сохраняются в исходном корпусе,
manifest и source-map; представление сайта и ранжирование поиска не меняются.
Усечённый текст читается с большим `body_limit` или по известной секции через MCP.

Проверки: `python -m unittest tests.test_v8std_mcp_references
tests.test_v8std_mcp_presentation tests.test_v8std_mcp_server
tests.test_v8std_mcp_runtime tests.test_v8std_mcp_tools_only`.
