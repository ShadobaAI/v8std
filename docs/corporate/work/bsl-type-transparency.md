# Прозрачность типов BSL-кода для рабочих проектов

### Общий принцип

Новый и изменяемый код должен быть прозрачен для статического анализатора EDT
и соответствовать методической рекомендации
[«Типизация кода»](https://github.com/1C-Company/v8-code-style/blob/master/docs/checks/code_typification.md).

### Контракты методов

Указывайте тип каждого параметра экспортного метода и возвращаемого значения
функции в документирующем комментарии. Для неэкспортного метода указывайте типы,
когда EDT не может надежно вывести их из прямого контекста вызова. Соблюдайте
форматы [#std453](../../std/453.md) и [#std641](../../std/641.md).

### Локальные переменные

Не объявляйте локальные переменные через `Перем`. Инициализируйте переменную
значением требуемого типа до первого использования и до входа в условие или
цикл, если она используется после него. Не меняйте тип уже инициализированной
переменной или свойства объекта данных и не маскируйте несовместимые типы
типизирующим комментарием.

### Переменные модуля

Переменные модуля снабжайте комментарием с типом и инициализируйте начальным
или пустым значением соответствующего типа.

### Структуры и коллекции

Ключи `Структура` и `ФиксированнаяСтруктура` создавайте сразу со значением
требуемого типа, не меняйте их тип и добавляйте ключи в области видимости, где
они затем используются. Для коллекций указывайте тип элементов и не смешивайте
несвязанные типы.

### Табличные данные и конструкторы

Для `ТаблицаЗначений`, `ДеревоЗначений` и их строк описывайте используемые
колонки и типы. Сложные объекты данных создавайте через функции-конструкторы
`Новый...`, `Новая...`, `Новое...` с полным описанием возвращаемого значения.
В параметрах экспортных методов предпочитайте ссылку `см.` на такую функцию
вместо повторного описания состава.

### Универсальные контейнеры

После получения значения из временного хранилища или другого универсального
контейнера восстанавливайте тип ссылкой на функцию-конструктор или
функцию-получатель. Локальный типизирующий комментарий используйте только когда
тип нельзя сделать прозрачным структурой кода или ссылкой на конструктор.

### Строгая типизация

Добавляйте `//@strict-types` в новые модули либо в существующие модули после их
полной адаптации. Не включайте строгую типизацию автоматически в legacy-модуле
ради локального изменения.
