# Соглашения для запросов

### Параметры и поля

Передавайте внешние значения через параметры запроса. Не подставляйте значения
и не собирайте условия конкатенацией строк. Выбирайте только используемые поля и
задавайте источникам и полям понятные псевдонимы.

### Форматирование

В многострочном запросе располагайте каждое выбираемое поле и соединение с новой
строки, пишите ключевые слова прописными буквами и разделяйте логические блоки
пустыми строками. Простой запрос к одному источнику можно записать в одну строку,
если он остается читаемым и соответствует [#std444](../../std/444.md).

### Временные таблицы

Имена временных таблиц начинайте с `ВТ_`.

### Установка параметров

Параметры, установка которых не
зависит от условий, устанавливайте сразу после создания объекта `Запрос`.

### Проверка наличия

Если требуется только проверить наличие данных, выполните запрос один раз и
вызовите `Пустой()` у `РезультатЗапроса` по [#std438](../../std/438.md). Не
выгружайте результат и не подсчитывайте строки.

### Обработка результата

Обрабатывайте результат через выборку, если вызывающему коду не нужна именно
`ТаблицаЗначений`. `Выгрузить()` допустим, когда таблица значений является
необходимым результатом или входом следующей операции. Для потенциально
неограниченного результата соблюдайте [#std725](../../std/725.md).

### Запросы в цикле

Не выполняйте однотипные запросы в цикле без обоснования. Применяйте общий
запрос, пакет или другой способ из [#std436](../../std/436.md). Допустимые
исключения и порционная обработка определяются этим стандартом, а не абсолютным
проектным запретом.

### Предопределенные значения

Для предопределенных элементов соблюдайте контекст и возможность отсутствия по
[#std443](../../std/443.md) и [#std697](../../std/697.md). Не заменяйте эти
условия безусловным требованием прямого обращения через менеджер.
