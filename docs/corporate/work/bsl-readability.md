# Читаемость BSL-кода в рабочих проектах

### Параметры

Требования к параметрам определяет [#std640](../../std/640.md), а к передаче
между клиентом и сервером — [#std636](../../std/636.md).

### Поток управления

Используйте ранний `Возврат` для предусловий и завершения обработанного сценария,
если он упрощает основной поток. Не применяйте ранний выход, когда он скрывает
обязательную финализацию, освобождение ресурсов или завершение транзакции.

### Границы метода

Метод должен решать одну ясно сформулированную задачу. Выносите самостоятельный
фрагмент логики, если это упрощает понимание, повторное использование или
тестирование; не дробите связную логику ради формального количества строк.

### Комментарии

Обычный комментарий должен объяснять причину решения, ограничение или
неочевидное бизнес-правило, а не пересказывать код. Актуализируйте связанные
комментарии вместе с логикой и удаляйте устаревшие.

### Литералы

Для чисел применяйте [MagicNumber](../../diagnostics/bslls/MagicNumber.md).
Локальное дополнение: неочевидные строковые литералы также заменяйте именованными
переменными, параметрами, перечислениями или константами. Пустая строка допустима,
если смысл следует из контекста.

### Булевы условия

Если выражение гарантированно имеет тип `Булево`, используйте его в условии
напрямую и применяйте `Не` для отрицания. Сложное условие разбивайте на
именованные булевы переменные или функции, когда это раскрывает предметный смысл.

### Результат функции

Основной результат функции возвращайте оператором `Возврат`, а не изменяемым
выходным параметром. Выходные параметры допустимы для контрактов платформы
или нескольких связанных результатов.

Не вводите локальную переменную только для присваивания одного выражения
или условия без побочных эффектов и немедленного возврата этой переменной.
Возвращайте выражение непосредственно, если нет оснований сохранить переменную,
перечисленных ниже. Значение, свойство или результат вызова также можно возвращать
напрямую, если выражение понятно и его результат не требует дальнейшей обработки.
Это допустимо и после подготовительных действий, и внутри цикла: сложность
функции сама по себе не требует отдельной переменной для возврата.

Сохраняйте переменную результата или именованную промежуточную переменную,
если значение проверяется, обрабатывается, используется повторно, постепенно
формируется или накапливается либо изменяется в нескольких ветвях. Переменная
также оправданна, если нужна для явного указания типа или существенно улучшает
читаемость сложного выражения, даже когда сразу после присваивания следует возврат.
Выбирайте имя, раскрывающее содержимое или назначение значения.
Имя `Результат` допустимо в простой функции, когда смысл значения очевиден
из контекста, а переменная нужна для его проверки, постобработки или повторного
использования.

Если возвращаемое значение уже находится в переменной, возвращайте эту
переменную напрямую. Присваивание её значения другой переменной, в том числе
`Результат`, только для последующего `Возврат` избыточно и не допускается.
Не переименовывайте содержательную переменную в `Результат` только потому,
что функция возвращает её значение.

### Временный код

Применяйте [#std456, пункт 3](../../std/456.md) к закомментированному коду
и служебным отметкам разработки. Локальных исключений для `TODO` и `FIXME` нет.
Условный оператор `?(...)` используйте только для простого выбора значения
без вложенности и побочных эффектов.
